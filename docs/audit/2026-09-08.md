# ytamp audit — 2026-09-08

> Historical baseline. The subsequent fixes and verification are recorded in [the fix report](2026-09-08-fixes.md).

Audited the current working tree on macOS, including the pre-existing uncommitted changes in `src/app.rs` and `src/ui/rows.rs`. No application code was changed. The additions are this report, evidence, and `examples/audit_probe.rs`.

**Fix first:** the Winamp return-to-main crash, context-menu input handling and overflow, and missing request/session identities. These affect basic interaction or state correctness.

## Verification and scope

Built and launched the native application with `cargo run --offline --bin ytamp`. Used macOS Accessibility and CoreGraphics mouse/keyboard events after Accessibility permission was enabled, and captured individual application windows. The app authenticated using its existing saved sign-in. Network-backed library loading, playlist opening, search, album opening, playback, pause/resume, seek dragging, next-track, queue toggling, and adding a track to the local queue were exercised. Winamp opening, its title menu, scale changes, playlist-panel opening and closing the mode were exercised too.

No online like/unlike, playlist creation/removal, or sign-out was performed. Those state transitions were exercised offline with synthetic data and the production reducer. Actual audio-device output was started and its position advanced; audio fidelity was not assessed. This is a broad functional audit, not exhaustive certification of every skin, operating system, media key, network failure or authentication flow.

It does not start the effect runtime, use credentials, access the network, or write an account's data. [Recorded output](evidence/probe-results.txt).

## Findings

### 1. P1 — Returning from Winamp can crash the entire app

**Native observation:** reproduced three times across two runs with backtraces plus the initial run. Open Winamp, change scale or open its PL panel, then click the top-right close control to return to the main window. The process exits with:

```text
context to have a current view
 glutin::api::cgl::context::ContextInner::is_view_current
 eframe::native::glow_integration::change_gl_context
 eframe::native::glow_integration::GlowWinitRunning::run_ui_and_paint
```

A direct close immediately after a fresh launch succeeded; the failure is not every close. Two failures followed an open playlist panel, and another followed changing scale. The first failure occurred during a close followed by an attempted resize; the later backtrace reproduced during the window transition before a subsequent resize obtained a window.

[Backtrace excerpt](evidence/winamp-crash.txt). Relevant application boundary: [src/app.rs](../../src/app.rs), `winamp_window` and `App::ui` (lines 48–86 and 139–155). The root window is hidden while an immediate child viewport exists, and closing the mode removes that child while restoring the root.

**Improvement:** isolate the multi-viewport OpenGL lifecycle into a minimal native reproducer and fix the context/window teardown ordering, or validate an alternate rendering backend. The backtrace locates the failing dependency path; it does not by itself prove which app or dependency change is the correct fix. Add repeated native open/resize/PL/close coverage. Headless reducer tests cannot catch this crash.

### 2. P2 — Right-click dead zones on track rows

**Native and offline reproduction:** a right-click on a title or empty row space opens the menu; a right-click on an artist link or the `+` button does nothing. The offline probe also confirms the album link fails. Native debug output reports `secondary_clicked=false` for the row and a different clicked widget ID on the failing positions.

Source: [src/ui/rows.rs](../../src/ui/rows/mod.rs), `track_row`, `row_context_menu`, `row_content`, `artist_label`, `album_label` (lines 156–207, 349–410). Only the parent response gets a context menu; interactive child responses receive secondary clicks themselves. Disabling selectable plain labels does not fix clickable child widgets.

**Improvement:** give the entire row one coherent secondary-click path, while retaining artist/album/queue primary-click actions. Use stable row identity including list and item identity. Test opening and selecting an action over every child control. The positive control verifies that a working menu queues the intended track.

### 3. P2 — “Add to playlist” becomes unreachable for a large library

**Native and offline reproduction:** open a track's context menu, hover “Add to playlist,” then try scrolling its submenu. With the current library the menu extends past the bottom of the viewport. Lower playlists and “New playlist...” cannot be reached by scrolling. The offline probe repeats this with 80 synthetic playlists and ten large wheel events.

[Native screenshot after scrolling](evidence/playlist-submenu.png). Source: [src/ui/rows.rs](../../src/ui/rows/mod.rs), `add_to_playlist_menu` (line 229): an unbounded loop of buttons without a scroll area.

**Improvement:** cap menu height and width, add a scrollable/searchable playlist list, and keep “New playlist...” separately accessible. Include a narrow-window and large-library interaction test.

### 4. P1 — Sign-out does not invalidate in-flight account responses

**Offline reproduction:** start signed in, reduce `SignOutRequested`, then deliver an old `LikedPageLoaded`. The supposedly reset state accepts the old account's tracks. A synthetic late `AuthVerified(Ok(()))` also changes signed-out state back to signed-in; its real-world reachability depends on overlapping authentication work.

Source: [src/core/update.rs](../../src/core/update/mod.rs), `sign_out`, `finish_sign_in`, `finish_liked_page` (lines 286, 297, 669), and [src/runtime.rs](../../src/runtime/mod.rs), `run_api_request`, `execute_api_request`, `clear_credentials`.

The runtime spawns tasks, clones the API into existing requests, and clears only the current API slot on sign-out. Results have no session generation. Stale data can repopulate state and generate cache writes after clearing, or arrive during a subsequent account session.

**Improvement:** stamp every account-scoped request/result with a session generation, invalidate it at sign-out/account change, reject stale completions and cache writes, and cancel work where possible. Test delayed completions across sign-out and sign-in to another account.

### 5. P2 — Older searches can overwrite newer results

**Offline reproduction:** submit “old,” submit “new,” complete “new,” then complete “old.” The input still says “new” but the displayed results belong to “old.”

Source: [src/core/action.rs](../../src/core/action.rs), `SearchLoaded`; [src/core/update.rs](../../src/core/update/mod.rs), line 53; [src/runtime.rs](../../src/runtime/mod.rs), search execution. Results carry neither a query nor a request ID and are always applied.

**Improvement:** track the active search generation and ignore earlier completions. Test both completion orders and a late error after a successful newer query.

### 6. P2 — Winamp loses application keyboard shortcuts

**Native reproduction:** Space pauses/resumes in the main window and Cmd+Shift+M opens Winamp. With the Winamp viewport active, both shortcuts stop doing their jobs. Mouse controls remain responsive. [Screenshot](evidence/winamp-keyboard.png).

Source: [src/ui/mod.rs](../../src/ui/mod.rs), `keyboard_shortcuts` (line 58), versus [src/ui/winamp/mod.rs](../../src/ui/winamp/mod.rs), `show` (line 387). Shortcuts are read from the root UI; the active child viewport does not run that handler.

**Improvement:** use a shared shortcut-to-action function for the focused viewport, invoked from both shells. Preserve text-entry focus handling and avoid processing the same command twice.

### 7. P2 — Overlapping playlist creates attach the wrong track

**Offline reproduction:** request playlist “first” from track A, request “second” from track B before the first finishes, then complete them in order. The first completion uses B; the second has no pending track left.

Source: [src/core/state.rs](../../src/core/state.rs), `pending_playlist_track`; [src/core/update.rs](../../src/core/update/mod.rs), `request_playlist_create` and `finish_playlist_create` (lines 1187, 1213).

**Improvement:** carry request identity and the intended track with each creation completion, or serialize creation with an explicit pending state. Keep failures and retry drafts associated with their request. No real playlists were created for this test.

### 8. P2 — Main queue entries have no actions

**Native and offline reproduction:** click or right-click an upcoming entry in the main queue panel. Nothing happens. Adding to the queue from a track menu does work.

Source: [src/ui/queue.rs](../../src/ui/queue.rs), `upcoming_entries` (line 34). The row response is discarded and the view has no action output, despite rendering through a clickable row helper. `QueueJumped` already exists for Winamp.

**Improvement:** wire queue rows to jump actions, then add explicit removal and clear controls with appropriate queue semantics. Make main and Winamp queues offer consistent essential operations.

### 9. P2 — A failed library load cannot be retried by reopening Library

**Offline reproduction:** set liked songs and playlists to failed, navigate away and back. No fetch is issued. The views offer only the error text.

Source: [src/core/update.rs](../../src/core/update/mod.rs), `fetch_missing_library` (line 209), and [src/ui/library.rs](../../src/ui/library.rs). Only `NotAsked` triggers fetching; `Failed` remains stuck.

**Improvement:** expose Retry/Refresh and allow failed loads to transition back to Loading. Preserve cached content on refresh failures where possible.

### 10. P2 — Pause is ignored during loading

**Offline reproduction:** begin `ContextPlayed`, then send `PlayToggled` before a decoder starts. It returns no effects and stays Loading. The main UI shows a pause icon during this time, but the click cannot prevent eventual playback.

Source: [src/core/update.rs](../../src/core/update/mod.rs), `toggle_play` (line 792); [src/ui/player_bar.rs](../../src/ui/player_bar.rs), `play_pause_icon`.

**Improvement:** separate desired playback state from decoder readiness, so a pause during loading is honored when the stream becomes ready. Cover slow loads and repeated play/pause input.

### 11. P2 — Layout clips controls and overlaps text at the supported minimum width

**Native reproduction:** resize to 700 points wide. Long liked-track text runs into the duration/queue controls, and the final Winamp button in the player bar falls outside the visible window. [Screenshot](evidence/minimum-window.png).

Source: [src/ui/rows.rs](../../src/ui/rows/mod.rs), `row_content`; [src/ui/player_bar.rs](../../src/ui/player_bar.rs), horizontal layout; [src/main.rs](../../src/main.rs), advertised 700-point minimum width.

**Improvement:** reserve fixed control columns, constrain/ellipsize title and artist text, and use a compact player layout when space runs out. Test the longest plausible titles with the queue both open and closed.

## Additional improvements

- **Font coverage:** native screenshots contain missing-glyph boxes in Japanese titles. Provide an appropriate fallback font strategy. Winamp's text rasterizer explicitly uses only Inter (`src/ui/winamp/pixel_text.rs`), so it needs separate coverage too.
- **Playlist identity:** the playlist page always displays the literal “Playlist,” even when metadata includes its real title (`src/ui/playlist.rs:48`). Show the title and track count.
- **Search completeness:** the model includes playlists, but the search API builds `playlists: vec![]` and the view renders only songs/albums/artists. Either implement playlist search or narrow the advertised feature.
- **Usable controls:** label icon-only transport controls with tooltips/accessibility descriptions. Disable or identify unfinished Winamp controls such as EQ/balance rather than making them appear functional.
- **Documentation:** README still lists Winamp mode and playlist edits as future work, although substantial implementations exist; the runtime module comment still calls the player a stub. Align docs with current behavior and missing pieces.
- **Regression coverage:** keep fast reducer tests, add full-view interaction tests for menu selections and focus, and a native macOS viewport smoke test. Existing tests miss the child-widget dead zones and cannot see native OpenGL crashes. Move existing temporary right-click debug traces behind a log level once diagnosis is complete.

Recommended implementation order: native crash → row/menu behavior → request/session identity → queue/keyboard/loading controls → responsive layout and font coverage. Preserve the reducer/effects separation; the largest architectural gap is identifying asynchronous operations across their lifetime.
