## Decision

Keep one Rust crate and the existing functional core / imperative shell design.
Split large modules by responsibility. Remove confirmed duplication and generated output from the repository.
Preserve current behavior and public module paths during the work.

Use ICM Restructure mode with a small System map under `docs/map/`.
Use source links as the authority for behavior. Do not copy implementation details into parallel specifications.
Number migration phases, not Rust source directories.

Estimated implementation effort: 8–16 hours, subject to native regression failures and external path dependencies.

## Proposed structure

```text
ytamp/
  CLAUDE.md                 short task router
  AGENTS.md                 generated from CLAUDE.md
  Cargo.toml / Cargo.lock
  src/
    app.rs                  thin eframe lifecycle
    runtime/                external effect execution
    core/
      update/               domain transitions behind update::update
      queue.rs              queue ordering
      session.rs            durable session schema
      discovery.rs          discovery state
      ...                   existing focused modules
    api/
      official/             OAuth HTTP transport and account endpoints
      discovery/            discovery response decoding
      ...
    ui/
      components/           buttons, sliders, headings, focus
      rows/                 track lists and context menus
      discovery/            shelves and collection pages
      winamp/               shell, display, transport, menus, EQ
      ...
    player/                 decoder, mixer, EQ
    stream/                 source chain, buffers, downloads
    skin/                   archive decoding and bitmap layout
  assets/                   required fonts, skin, and licenses
  tests/fixtures/           retained behavioral inputs
  examples/                 supported diagnostics and generators
  scripts/                  repeatable checks
  docs/
    map/                    small ICM system map
    plans/                  approved work and historical plans
    audit/                  dated verification and referenced evidence
```

Start the map with four real clusters: account/catalog, playback, default UI, and classic skins.
Each card states ownership, source paths, inputs/outputs, and first-order change impact.
Add process cards only for actual flows: sign-in, Home loading, playback, and skin loading.
Generate `AGENTS.md` and `routing.md` from each map `CLAUDE.md`, as required by the System map form.
A check must reject drift between generated copies.
Keep the root router below about 60 lines.

## Five implementation phases

### 1. Secure the baseline and add the ICM router

Snapshot the complete dirty worktree, including untracked files, outside the repository.
Use a dated archive under `/Users/suvojit/programs/ytamp-refactor-archive/`.
Verify hashes and the archive manifest before any move or removal.
Do not discard existing user changes or reset the repository.

Create the small map and its generator/checker. Check four cold walks against actual source paths.
The approval here authorizes map creation. Each later slice still needs a cold walk before it advances.

Exit check: baseline tests and native cases have a recorded result, and all four map routes resolve.

### 2. Remove repository noise and simplify diagnostics

Redirect RustyPipe storage and reports into the OS cache directory.
Then archive the current generated files and remove them from Git tracking.
Extend `.gitignore` for runtime artifacts that can recur.

Consolidate shared diagnostic setup only where two or more probes use the same path.
Retain the skin generator, compatibility probe, preview harness, stream probe, and OAuth integration checks.
Keep write diagnostics opt-in. Do not run them during this refactor.

Two pairs of audit logs have identical bytes. Consolidate them only with their incoming links.
Keep the existing binary assets, licenses, test fixtures, and linked screenshots.
Leave the unrelated research document in place unless the owner chooses its archive destination.

Exit check: supported probe commands still compile, links resolve, and launching the app does not recreate root-level runtime files.

### 3. Split the core and external effects

Extract reducer branches into account, catalog, playback, and navigation handlers.
Keep the outer request-generation and playback-generation guards intact.
Split runtime execution by effect owner. Share cancellation and delivery rules through a small explicit boundary.
Split account transport from endpoint parsing. Keep the existing Api facade.

Use named input types instead of ambiguous boolean combinations where that improves callers.
Keep side effects at runtime, storage, player, and platform boundaries.
Do not introduce a generic workflow engine, a new dependency-injection framework, or extra crates.

Exit check: stale responses, OAuth retry, cache races, queue ordering, radio cancellation, seek, and session restoration retain their behavior.

### 4. Split UI composition and finish complexity reduction

Separate layout decisions, interaction handling, and paint within the current default UI.
Use shared controls for repeated behavior. Keep classic bitmap controls separate.
Split Home, discovery shelves, lyrics, track rows, skin browser, and Winamp shell responsibilities.
Keep widget IDs stable during file moves.

Measure all edited functions. Address the remaining measured hotspots in queue, skin installation, and audio processing.
Keep low-complexity functions intact unless the module boundary requires a move.
Do not rewrite decoder or equalizer algorithms to improve file size.

Exit check: paint and input tests pass. Native layout, menus, scroll restoration, and skin checks match the baseline.

### 5. Review removals and run the release checks

Audit dependencies with a Rust-aware tool and the Cargo feature graph.
Remove a dependency only after checking production, examples, tests, target-specific code, and generated assets.
The current audit did not establish any dependency as unused. Cargo machete is not installed.
Pin the wildcard image dependency without an unrelated upgrade if the resolved version supports all current codecs.

Generate the final inventory, reference report, and complexity comparison.
Check the ICM walk again. Remove temporary migration material only after parity and references pass.

Exit check: no unresolved moves, no lost commands, no broken links, and no claimed cleanup without evidence.
